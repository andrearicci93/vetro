What each Vetro switch changes on a Samsung TV (0.7.2)

Updated 27 November 2026 · Updated on 2026-11-27 against the Vetro 0.7.2 README, CHANGELOG, UPDATING.md and MQTT guide at tag v0.7.2 (commit 2ee0456), with the 0.7.1 CHANGELOG, UPDATES-WITHOUT-ROOT.md and INPUTS.md as checked the same day at commit cbc363f; the rest was rebuilt on 2026-11-21 from VETRO-UI.md, TUNER.md, the dashboard's own labels, DOMAIN-FILTER.md, SIGN-IN.md and RELEASE-0.5.0.md.

Each Vetro switch does one specific thing on the TV: it sets a disable flag on a group of components, writes a file that a Samsung service checks, stops or masks services, or changes one menu value. This page describes Vetro 0.7.2 (released on 2026-11-27), which follows 0.7.1 (2026-11-26) and 0.7.0 (2026-11-21). It lists what each switch does, how to undo it, and what the project says is not yet verified, using the README, the CHANGELOG and the documents they link.

Vetro is experimental and needs root, and it ships no signed installer: Vetro's root requirements and the risks of rooting come first, and Apps2Samsung does the signing. Most effects were tried on one Samsung Q80A. Where the changelog says a part was not tried on a TV, the table says so.

What do the Quick settings switches do?#

Quick settings opens on General; its other tabs are Privacy and ads, Voice, Disable, Experimental (new in 0.7.1), Uninstall and Developer settings. Each switch reports Done, Partly done or why it is unavailable on your TV. Since 0.7.1 a switch that stops apps checks each one by its own process afterwards and reports one that is still running, instead of trusting the stop's answer, and some switches below say Partly done in new cases. Controls that need root show Root required while root is disconnected. The undo column uses only behavior the changelog, README or dashboard documents; where none is documented, it says so.

Essential settings (in General)#

This section held the firmware switch in 0.5.0 and was renamed in 0.7.0.

Switch What it does on the TV How to undo it Status and caveats
Block firmware and software updates Stops and masks the update services Vetro knows about, not only the menu's Auto update: over-the-air firmware, Samsung's background app and package updates, app-binary downloads, system components and the preview updater. It turns the Auto update and app-binary switches off, removes download markers and applies the lock again after every restart: at power-on through the AT-HUB boot step where the TV has one (Tizen 6, 6.5 and 9), otherwise when Vetro's root agent starts. Since 0.7.1 it also removes Samsung's request to restart into its separate update mode, which starts before any app and installs from Samsung's servers: when the switch is turned on, at every restart and, through a small system unit, as soon as the request is written. It keeps Samsung's own setting for downloading an update too big for the TV's storage in that mode off, also at every restart, stops one more update service (the helper the app-binary updater uses to say a download is ready) and adds two update servers to Vetro's DNS blocking list Switch off: the services are unmasked and the previous Auto update value comes back. Samsung's update-mode setting is turned back on only if it was on when the switch was turned on, and only the DNS names Vetro added are taken out. The vendor boot script returns once Quick boot is off too. Restore the TV turns both off Off by default and needs root. Read from the Tizen 6, 6.5 and 9 firmware. On a Q80A (firmware 2310.0) the masks were in place after a cold reboot, before Vetro's service; it was not tested against a forced update, and other models are not tried. The switch is designed to block Samsung's automatic firmware and app updates. USB recovery is left working, but a USB update from the TV menu needs the switch off. A firmware update that lands anyway replaces everything it does (#223). An update reached a QE65S85F with the earlier block on, and what happened there is not known yet (#308). The 0.7.1 parts are not tried on a TV yet. A TV that had the switch on before 0.7.1 gets them by itself at the first start of 0.7.1; the switch reads Partly done when the new guard is not running. The two servers are blocked only while Enable DNS blocking is on and Vetro runs (CHANGELOG)
Disable background app delivery New in 0.7.1. Shown only on a TV that has its services; the changelog gives no more detail Switch off (the README says every switch can be turned back on) The idea came from samshush, and the changelog says those ideas were checked on a Q80A; no other test is recorded
Allow SDB from the local network Opens Vetro's SDB tunnel to clients on your network, so developer tools reach the TV's Samsung Debug Bridge, which installs apps and runs shell commands. The tunnel does not use Vetro pairing. The dashboard says turning it on improves compatibility with Apps2Samsung and TV-Store Switch off, which disconnects them. Restore the TV turns it off Moved here from Developer settings in 0.7.0. Off by default, asks for confirmation and stays on after restarts until you switch it off. See the security model

Why the firmware switch matters, and what it cannot promise, is covered in will a firmware update remove root and stopping Samsung TV auto updates. In short: turn it on while root still works. It can help keep root; it does not guarantee it.

How does the domain filter choose its names?#

The filter matches exact hostnames: blocking samsungads.com does not block rtb-config.samsungads.com. The candidate names come in three groups, described in DOMAIN-FILTER.md.

  • Firmware-derived names are strings found in the Q80A firmware image, each tied to the component that references it. Whether a name is reached at run time, and what happens when it is blocked, was not tested on a TV.
  • Reported names come from public reports. None of them is in the firmware.
  • One probable name, gpm.samsungqbe.com, is a guess at where the viewing-data service learns its servers. It is not in the firmware and not confirmed in traffic, so the dashboard labels it unverified.

The filter refuses the names the TV uses for its internet check, its clock and Samsung's Certificate Manager. The software-update servers are not on that list. The Q80A firmware references them, but blocking these names alone does not cover every update connection, so the project points to its Quick settings switch, now Block firmware and software updates, which stops the other update services Vetro knows about and is easier to undo. The usage-log domain that Stop viewing-data collection adds to your saved list does not turn the filter on: DNS blocking stays your choice, and the data service can still run until it is on. Since 0.7.1 the DNS blocking page has one more group: the two update servers that Block firmware and software updates adds (otn2.samsungcloudcdn.com, qoe.samsungcloud.tv), which are also in the lists for your router.

What do the Vetro UI options change?#

Everything Vetro draws on the TV is switched on the dashboard's Vetro UI page, which the side menu marks Preview: the launcher, live TV (Vetro TV Tuner), the volume bar and the number pad. Its Overview tab has one switch per part, and the Vetro UI guide says some parts may not work on every TV yet. The page, the switch-over between launchers and the automatic remote interception are tested on the computer only. Report problems in a GitHub issue with the diagnostic report from Quick settings → Developer settings → Diagnostic report.

The launcher is off until you turn it on, after an in-page warning. Turning it on closes Samsung's Home and switches off the Autorun Smart Hub setting so the TV no longer powers on to Samsung's Home. Vetro remembers the old value and puts it back only if it changed it. Nothing is removed: if the launcher stops, the Home key goes back to Samsung's Home. Only one launcher answers the Home key at a time: Samsung's Home, the Vetro launcher or another app. Why the launcher is native explains the design.

What do the Apps and processes actions do?#

Apps and processes, the dashboard page called Task manager before 0.7.0, lists every app and service on the TV with a plain description and a role: Tracking, Optional or Keep. Since 0.7.0 the name Task manager belongs to the Control center card on the TV. The Not used at home role was removed in 0.5.0. Hotel, shop and factory apps open only after a warning.

Action Effect Undo
Disable Sets a disable flag. The component stays installed Enable it again
Stop Ends the running process It may start again by itself; a stopped service returns after a restart unless something holds it off
Uninstall Removes the package and all its components Needs an installer to recover. Keep removed apps removed will keep it off until you select Allow again

Protected system components cannot be touched. Uninstall removes the whole package with all its components, so Vetro refuses it when any component in that package is protected. Quick settings and Apps and processes share one inventory, so an assistant disabled in one shows as disabled in the other. Since 0.7.1 a background service you disable here also gets Samsung's own "do not start" file where a Disable switch uses one (Gaming Hub's daemon and the voice services), and enabling it again takes the file away.

What do the other tabs change?#

The Remapper turns a remote key into an app launch, or, since 0.7.0, into another key: an input (TV, HDMI 1 to 4), play and pause keys, Home, Back, OK, the arrows or volume (Send key in Step 2). Shortcuts survive restarts, and a key can also send an MQTT message (remapping Samsung remote buttons). Since 0.7.1 a key can also run Turn off screen: Samsung's Picture Off, so the picture goes off while the sound plays on. The same key, or any key except Volume and Power, turns it back on. It works while the remote interception is on and the remote is held by Vetro, and it can be set from Home Assistant and HTTP rules too. On a Q80A the TV's power state went to Picture Off within 0.3 s and the same key woke it; the panel itself was not watched (CHANGELOG). Since 0.7.2 a shortcut, or a Home Assistant or HTTP rule, can be limited to the moments the picture is on or off; if Vetro cannot read the picture state the rule does not run, and the changelog says this is tried in unit tests and the preview only, not yet on a TV. In 0.7.2 keys sent through POST /control also take the Remapper's route to Vetro's tuner, the launcher and the volume bar, tried on a Q80A (#315); keys from Samsung's own remote server (SmartThings, the TV's WebSocket) are not covered. Power and DisplayPort are new keys to send: on a monitor, Power toggles standby, and DisplayPort is for Samsung monitors, since a TV has none. On a monitor whose source list holds exactly one HDMI, one DisplayPort and one USB-C port, such as the Odyssey OLED G8, the Remapper, the launcher's Sources and Home Assistant offer those three inputs (#314). Settings and controls writes supported picture and advanced settings with read-back, and restore of saved values; since 0.7.1 Settings and controls → Network and inputs → Inputs shows one button per available input on TVs and monitors (INPUTS.md). The Home Assistant tab publishes the TV's state, since 0.7.1 with a Channel sensor while Vetro's tuner runs and the input is TV and since 0.7.2 with a Power state sensor tried only in unit tests so far, and accepts actions on exact topics; since 0.7.2 it also changes channel through a Tune channel box (CHANGELOG) (Home Assistant and Samsung TV). Shards, on the dashboard's Vetro Shards page, are third-party extensions with the same access as Vetro, off until you switch them on.

Is every switch reversible?#

Turning a switch back is the documented undo, but it only works while Vetro and its root helper stay reachable, and it is not a promise to recover from every failure, such as lost network access or a TV that stalls its boot. Restore the TV puts back what Vetro recorded and lists what needs manual recovery. A firmware update that installs anyway replaces the system software, and with it every change Vetro made, root included. Since 0.5.0 the dashboard asks for a six-digit code shown on the TV once the Vetro app has been seen; see the security model, and the uninstall guide for removal.
