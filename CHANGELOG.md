# Changelog

## 0.5.0 — 2026-11-06

> **Republished (7 Nov 2026).** The first 0.5.0 build had pairing always on. On a Samsung Q8F (Tizen 9, firmware 1300.9) the Vetro app on the TV could not reach the service, so the pairing code never appeared and the dashboard could not be opened. This republished 0.5.0 makes pairing automatic (open until the TV app is seen), keeps readable refusals on the TV screen (**"Refused this screen"** with the address and Origin the service saw) and fixes the TV's address list on some Node versions. **If you installed 0.5.0 before this note, reinstall with Apps2Samsung**: in-place update does not offer it, because the version number is the same. The two builds differ only by their source revision in the diagnostics report. Not yet tried on a Q8F; reports welcome.

Pairing for the dashboard and API, community plugins (Vetro Shards), a custom launcher, more privacy switches, signed in-place updates and a safer Restore the TV. There was no 0.4.0 release: its work is included here.

### Sign-in, plugins and updates

- **Pairing for the dashboard and API** ([#5](https://github.com/andrearicci93/vetro/issues/5) requested by **PythEch**; [#9](https://github.com/andrearicci93/vetro/pull/9) by **zerodevb**). Browsers and scripts pair once with a six-digit code shown on the TV. Up to 20 devices can be paired. The TV app keeps working without pairing. Pairing is **automatic**: it switches on by itself the first time the Vetro app on the TV is seen, which proves the TV can show the code. [Sign-in guide](app/docs/SIGN-IN.md).
- **Pairing is automatic, and you can choose.** Quick settings → Developer settings → Pairing has a **Require pairing** switch. By default it is automatic: until the Vetro app on the TV has been seen, the dashboard is open like Vetro 0.3.5 and says so; after that, pairing is required. Choosing On or Off replaces the automatic mode. Turning it off asks for confirmation. Restore the TV does not change it.
- **Vetro Shards (plugins), experimental.** Install, update and remove `.vplugin` bundles from a public catalog or a file. New plugins start switched off, and a plugin that keeps failing is stopped. If Vetro was stopped right after starting, plugins start in safe mode and the page says why; nothing is removed. Plugin pages open as tabs. Plugin code has the same access as Vetro, including root commands: permission labels are not a security sandbox. [Guide and developer tools](app/docs/plugins.md).
- **Signed plugin catalog.** Catalog plugins are checked against a signature, and invalid ones are refused. Unsigned plugins need **Developer mode**, which is off by default. Each plugin shows where it came from. A signature shows who published a plugin, not that it is safe. Plugins with accented characters now install on older TVs.
- **The launcher is the first bundled plugin.** It updates with Vetro and cannot be removed or replaced from the catalog. [Architecture](app/docs/PLUGIN-ARCHITECTURE.md).
- **Signed in-place updates, launcher included.** Software update checks GitHub when you ask, verifies the bundle, replaces the files and restarts the launcher if needed. If the new version does not start, Vetro goes back to the previous one within four minutes; you can also roll back by hand. A second update is refused while the first one waits for confirmation ([#116](https://github.com/andrearicci93/vetro/issues/116), reported by **adri0894-web**). Changes to `config.xml` still need a reinstall. Tested on a Q80A with the release key: update, refusal of a tampered bundle, rollback by hand and automatic rollback. [Update guide](app/docs/UPDATING.md).

### Launcher and remote

- **Custom launcher: your own app on the Home key.** The Launcher page has two tabs, **Vetro launcher** and **Custom launcher**. Pick an installed app and turn the switch on: the Home key opens that app. Samsung's Home stays enabled, Vetro closes it after each Home press, and Autorun Smart Hub is switched off so the TV does not power on into it. Turning the switch off undoes all of it. If the app keeps failing to start, the mode turns itself off and the Home key goes back to Samsung. Keep Samsung's Home enabled: on the Q80A, disabling it can keep the TV from finishing its boot. The separate **Samsung Home** switch is now at the bottom of the Custom launcher tab and asks for confirmation. Not yet tried by hand on a TV. Related request: [#127](https://github.com/andrearicci93/vetro/issues/127) by **skjnldsv** (an app on the TV's home screen at power-on); this mode does not cover it.
- **Faster, more reliable launcher keys** ([#23](https://github.com/andrearicci93/vetro/pull/23), [#24](https://github.com/andrearicci93/vetro/pull/24), adapted from **Firaenix**). Better key handling, and Samsung's Home panels that overlap the launcher are closed. **Reduce motion** turns off all launcher animations. Choosing Samsung Home right after pressing Home no longer closes it again.
- **HDMI sources in the launcher** ([#34](https://github.com/andrearicci93/vetro/pull/34) by **tomcraft**). Two switches in the Launcher tab, both off by default. *HDMI sources on Home* shows the HDMI tiles already in Samsung's Home row, in the same positions. *HDMI source images* uses Samsung's artwork instead of generic icons. Tested by tomcraft on an S95C.
- **App lists on newer Samsung Home layouts** ([#43](https://github.com/andrearicci93/vetro/pull/43) by **arnaudaprahamian**, [#82](https://github.com/andrearicci93/vetro/issues/82)). On TVs where the Home row holds only recent apps, the launcher adds the other visible installed apps. Tested on a Q80A, where nothing changes; not tested on a 2022 TV.
- **Remapper and the on-screen keyboard** ([#143](https://github.com/andrearicci93/vetro/issues/143), [#59](https://github.com/andrearicci93/vetro/pull/59) by **domenix**). While remote shortcuts are active, keys that keep their normal action now work in Tizen's on-screen keyboard. Tested on a Q80A.
- **The TV app can reach Vetro through the TV's own address** ([#122](https://github.com/andrearicci93/vetro/issues/122), [#123](https://github.com/andrearicci93/vetro/pull/123), proposed by **skjnldsv**). If the local connection fails, the TV app tries the TV's network addresses so it can still show status and pairing codes. Not yet tried on a TV. Waking from standby or Art Mode, the other half of #122, is not covered.
- **Compatibility fixes from `main`.** Tizen 10 service startup, the 0.3.5 fixes and Node 4.4 support for the integration adapter on older TVs ([#75](https://github.com/andrearicci93/vetro/pull/75), by **Merennor**). Starting the service on Node 4.4 does not make root features available there.
- **Root compatibility checks.** Vetro checks which root runtime the TV can use and reports startup failures more clearly. Based on [samsung-tv-root v0.0.12](https://github.com/chris-ritsen/samsung-tv-root/releases/tag/v0.0.12) by Chris Ritsen and contributors (Unlicense). Tested offline only.

### Quick settings, privacy and maintenance

- **Disable tab.** The Memory tab is now **Disable**: HbbTV, Multi View autostart, Ambient and the new **Disable AirPlay**. **Keep removed apps removed**, in General and on by default, keeps apps you remove with the Task manager off the TV and checks every 10 minutes for ones that came back. Select **Allow again** before reinstalling one yourself. Turning the switch off stops the checks but keeps the list. Tested on a Q80A.
- **Disable AirPlay.** Stops the AirPlay receiver now and after restarts, so casting from Apple devices does not work while it is on. The switch appears only on TVs whose AirPlay setup supports it, and is included in Restore the TV.
- **HbbTV** now also stops its restart service, where the TV has one. Older installations may show "Partly done" until Vetro's service restarts.
- **Stop Ambient** is more reliable on the Q80A, and Ambient stays stopped after a restart. You can still open Ambient yourself.
- **Stop viewing-data collection.** Stops recognition, analytics, ad and usage-log services now and after restarts. The usage-log domain is added to your saved domain list; DNS blocking is not turned on for you. The data service can still run, so uploads may continue unless DNS blocking is on. Effects on recognition and suggestions have not been verified.
- **Restore the TV / Remove Vetro.** Shows the changes Vetro recorded and puts them back after one confirmation, with a result for each step. Uninstalled apps, settings without a saved previous value and changes made by plugins need manual recovery. If Vetro cannot read its saved state, it keeps its backups and blocks data removal. Deleting saved data and pairing is a separate confirmation.
- **Quick settings and Startup stay in sync.** Disabling a group clears its components' start-at-boot and auto-restart settings; enabling it restores them. A failed change is rolled back.
- **Allow SDB from the local network.** Quick settings → Developer settings → Developer access lets developer tools install apps and run commands through Samsung Debug Bridge without Vetro pairing. Off by default, asks for confirmation, and stays on after restarts until you switch it off. Restore the TV turns it off. [Security](SECURITY.md) · [Integration guide](rooting/README.md).
- **Clear leftovers** also removes old network logs, temporary Prime Video pictures and caches of apps that are not running. Settings, logins and other app data are not touched. The extended cleanup has not yet been checked on a TV.
- **Factory colour test guard** ([#135](https://github.com/andrearicci93/vetro/issues/135) reported by **9francy9**; [#137](https://github.com/andrearicci93/vetro/pull/137)). Opening Samsung's AgingApp could leave the TV starting a factory colour test at every boot, with the volume bar hidden, even after a factory reset. Vetro no longer opens AgingApp or the service menus, and asks for confirmation before opening other hotel, shop or factory apps. If the test is on, Quick settings offers **Turn off the factory test**. Tried only against a simulated TV.
- **Remote shortcuts stop with the service** ([#138](https://github.com/andrearicci93/vetro/issues/138), by **pponce**). When Vetro stops or is replaced, pending remote actions are cancelled and cannot run afterwards. Not yet tried on a TV.
- **Undo during startup** is respected: a privacy or Ambient change you undo is no longer applied again by pending retries.
- **Catalog and domain candidates.** App classifications from reports #14 (**Kuzekunn**), #17 (**REVANOX**) and #26 (**antonio1475**), and `rtb-config-canary.samsungads.com` as an untested domain candidate. The Home-picture host `cdn-stv.adgrx.com` (#79 by **RyanDChavez**; #109) stays out of the default lists: blocking it alone does not remove pictures already cached.
- Credit: the AirPlay switch, the restart check after a snapshot boot, the HbbTV restart-service stop and Keep removed apps removed come from **zabique**'s fork of Vetro (branch `fork/extras`); see Credits.

### Dashboard

- **Settings and controls** replaces *TV settings* and *TV controls*, with tabs for Picture and sound, Network and inputs, Privacy, Device and Remote keys.
- **Navigation by task.** MQTT is now Home Assistant, and Plugins sits under Remapper. Quick settings opens on **General** (software update, storage cleanup, firmware updates, Restore the TV, Remove Vetro), followed by Privacy and ads, Voice, Disable and Developer settings. Diagnostic report moved to Developer settings, and Resource monitor sits under TV next to Task manager. A new **About Vetro** window and the running version are in the side menu.
- **Vetro Shards** is the new name for the plugin system. Existing plugin files keep working. The plugin page has repository and guide links, a three-step install guide and separate Installed and Catalog sections.
- **Sign-in.** The sign-in page has the Vetro logo and three numbered steps. **Sign out** asks whether to sign out this device or all devices.
- **DNS blocking** is the new name for domain blocking everywhere in the dashboard.
- **Task manager.** *Running* and *Not running* filters now work with live updates off. The confusing "Not used at home" role is gone; hotel, shop and factory apps now show a warning before opening. Samsung Settings components can no longer be picked as launch targets; old rules load but skip them. Failed or slow app-list reads show their state and a Retry button ([#89](https://github.com/andrearicci93/vetro/issues/89) by **Ghakizu**, [#100](https://github.com/andrearicci93/vetro/issues/100) by **Licaa21**, #109).
- **TV screen and diagnostics** (#88, #106, #107). Clearer startup steps separate unavailable root support from a service still starting. Reports show model, firmware and Tizen version more reliably, and a stopped launcher is no longer reported as a failed check (#82/#108). Reports behind this work: [#82](https://github.com/andrearicci93/vetro/issues/82) **thatrandomtrooper**, [#83](https://github.com/andrearicci93/vetro/issues/83) **andreknieriem**, [#94](https://github.com/andrearicci93/vetro/issues/94) **BennoGAP**, [#101](https://github.com/andrearicci93/vetro/issues/101) **Nebarik** and [#104](https://github.com/andrearicci93/vetro/issues/104) **pponce** (the screen stuck on "Checking" or an incomplete report), [#87](https://github.com/andrearicci93/vetro/issues/87) **Hielkez**, [#17](https://github.com/andrearicci93/vetro/issues/17) **REVANOX** and [#25](https://github.com/andrearicci93/vetro/issues/25) **JamesMills818** (firmware and Tizen version missing), [#91](https://github.com/andrearicci93/vetro/issues/91) **FUSIONOF** and [#99](https://github.com/andrearicci93/vetro/issues/99) **lequan2909** (root on Tizen 9/10), [#2](https://github.com/andrearicci93/vetro/issues/2) **Merennor** (Node 4.4).
- **Optional component details in the diagnostic report.** Adds descriptions, requested permissions and startup details for unrecognised components, without file contents or paths. Off by default.
- **Reliability fixes** ([state-machine review](app/docs/STATE-MACHINES.md)). Vetro retries a failed root connection with a growing delay instead of every 8 seconds, and caps its diagnostic files at 256 KiB. A request or plugin timer that fails no longer stops the whole service. DNS blocking is restored even if root starts late. Saved remaps, sign-in sessions and launcher lists are written so a power cut is much less likely to corrupt them. A failed remote action pauses shortcuts for a minute instead of for good. Launcher: Home keys seen by the display server are handled, the first frame after reopening is current, and a held key no longer reaches the reopened launcher. Dashboard: the Privacy panel shows reported consents, conflicting shortcut saves are refused, leaving the Remapper ends listening, a request the TV never answers is cancelled after two minutes instead of locking a switch, unsaved domain text is no longer overwritten, and a plugin page stops running when you leave it.

## 0.3.5 — 2026-10-29

- **Select the TV tuner directly** ([#31](https://github.com/andrearicci93/vetro/pull/31), by tomcraft): `KEY_TV` and `XF86DiscretSourceTV` are now accepted by the native key control and by remapping actions, so a rule such as "back to live TV" can select the tuner instead of cycling through the sources. Checked by the author from an HDMI source and from a foreground app; whether the key exists is firmware-dependent, and on a TV without it the request does nothing.
- **Remote interception finds the remote again after Linux renumbers its inputs** ([#32](https://github.com/andrearicci93/vetro/pull/32), by tomcraft): a saved `/dev/input/eventN` is not a stable identity, and a remote that shows several interfaces under one name stayed disconnected after a restart or a reconnection. With several same-name interfaces, Vetro now picks the one that advertises keys (read from sysfs); if two or more do, it keeps the saved one when it is among them; if it cannot decide it leaves interception off instead of guessing. Replayed on five cases and checked by the author on a TV for the automatic reconnection; a real renumbering was not provoked.
- **The service can run on Node 4.4 (Tizen 4 and 5.5), app-only** ([#33](https://github.com/andrearicci93/vetro/pull/33), by SalustLab; issues #2 and #19): those TVs run the web service on Node.js 4.4.3, not Node 12, and the service stopped twice, while loading (`async` functions, `fs.promises`) and on the first request (`Promise.prototype.finally`, `Buffer.alloc`, `Buffer.from` with a string). A new `compat.js` adds the three missing built-ins only where they are absent, and the package reader is written with promise chains. Nothing changes on a runtime that has them. Tested by the author on a QN55Q80TAGXZD (2020, Tizen 5.5): the dashboard, the app list, the diagnostics and the start after a cold boot work, 45 requests ran without a crash. This is the app-only package: **no root** on that platform (no `/usr/bin/dotnet`, .NET Core 3.0, no mount namespaces), so the features that need root are not available. Not tried on a Tizen 4 TV.
- **Advertising list: two more components** ([#44](https://github.com/andrearicci93/vetro/pull/44)): `com.samsung.tv.iacr` and `com.samsung.tv.screen-analysis-dbmgr` are now listed as advertising in the Debloater and as tracking in the app catalog, instead of "other". Nothing is turned off by itself: each one is still disabled by hand, one at a time. Covered by the test suite and tried on a Q80A.
- **Home order on The Frame 2024 (Tizen 8.0)** ([#45](https://github.com/andrearicci93/vetro/pull/45); issue [#41](https://github.com/andrearicci93/vetro/issues/41), reported by Nyar-cloud): on firmware T-PTMDDEUC-1400.1 the Home order file ends with `EOFCOBA` (no space), and reading it failed with *Home order terminator missing*. Both `EOFC OBA` and `EOFCOBA` are now accepted, and the one found is written back unchanged when the order is saved. Covered by the test suite; not tried on a TV. The second problem in #41 (`csfs` coming back after pressing Home) is not fixed.
- **Dashboard: app ID shown when app names repeat** ([#52](https://github.com/andrearicci93/vetro/pull/52), by domenix): entries with the same name in the app pickers are different apps or menus; the app ID is now shown next to the name so they can be told apart.
- **TV screen redesign:** Vetro's screen on the TV shows its state more clearly, with a diagnostics panel and the app icon. While checking, it says what it is doing, and every check has a time limit so the screen no longer hangs on "Checking". The web dashboard is unchanged.
- **Installation guide** ([#39](https://github.com/andrearicci93/vetro/issues/39), by bertrandom): where the TV's DUID is shown, that `tizen install` should be used and `sdb install` can do nothing without an error, where the Tizen Studio tools usually are, and `sdb shell 0 vd_applist` to check that the installation reached the TV.
- **Installation guide: where to get Tizen Studio** ([#47](https://github.com/andrearicci93/vetro/pull/47), by bertrandom): Samsung's Tizen Studio page now redirects to its VS Code extension, so the guide links to the Tizen Studio installer directly.
- **Installation guide: open Vetro once after installing** ([#49](https://github.com/andrearicci93/vetro/pull/49); issue [#25](https://github.com/andrearicci93/vetro/issues/25), reported by JamesMills818): on some TVs the installer registers the service without on-boot and auto-restart. Since 0.3.2 Vetro sets them back, but only after the app has been opened once, so the install steps now say so. Documentation only.
- **Troubleshooting: "TV platform adapter unavailable"** ([#42](https://github.com/andrearicci93/vetro/pull/42)): the message means the package was built without the root integration (app-only); the fix is rebuilding with `node build.cjs` in `rooting/` (installation step 3).
- **Compatibility:** a Samsung Q80R QN65Q80RAFXZA (2019, Tizen 5.0, firmware T-MSMAKUC-1500.5) works with a personal port ([#35](https://github.com/andrearicci93/vetro/issues/35), by torresdrew): its own launcher host (.NET Core 2.1.4), the older app registry and icon layout, and Node.js 16.20.2. It is not the stock package and the changes are not merged; it is listed as working with local changes.
- **Compatibility:** a Samsung S90D QA65S90DAULXL (2024, Tizen 9, firmware T-PTMDUABC-0090-2130.0) on Vetro 0.3.2 ([#36](https://github.com/andrearicci93/vetro/issues/36), by Inderdeep29): service on Node v18.18.2 and the UID-0 root agent running, the Launcher on with 15 apps and no error, and, in the owner's account, the root agent back after a full restart.
- **Compatibility:** a Samsung The Frame QN75LS03BAFXZA (2022, firmware T-PTMAKUC-1720.7) on Vetro 0.3.2 ([#39](https://github.com/andrearicci93/vetro/issues/39), by bertrandom): service on Node v12.16.3 and the UID-0 root agent running; after the Host PC IP was set to `127.0.0.1` the service started by itself after a cold boot. The Launcher was not tried.

## 0.3.2 — 2026-10-26

- **Vetro starts at boot on TVs whose installer ignored the package's request** ([#29](https://github.com/andrearicci93/vetro/pull/29), by domenix; issues #4, #25 and #26): on an S90C (Tizen 7.0, firmware T-PTMCDEUC-2000.2) three clean installs registered `vetrotvapp.svc` with `app_onboot=false` and `app_autorestart=false`, although `config.xml` asks for `true` for both, so the service did not start after a restart (not within 3 minutes) until someone opened the app. The same registration shows in the reports for the QE55QN93AATXXC (#26) and the GU75CU7179 (#17). Once the root agent is connected, Vetro now puts those two flags back for its own service, once per service start and only when one is off, with the same backup-and-read-back write the Task manager uses. Checked on the S90C: started 40 to 65 s after a restart or a power cut. Nothing else is touched, and the Task manager still refuses to change Vetro's own flags. The root agent has to connect first, so a new install still needs the app opened once.
- **Community report check:** it now knows the `launcher` and `quickWins` sections (every comment since 0.3.0 said *plus 2 unrecognised*), and it reads the `firmwareSource`, `tizenVersion` and `components` fields that the next minor release adds, so reports from it are not flagged.
- **Correction to 0.3.1:** its notes said the Home cache moved on *2022* TVs. TVs with the new Home (`com.samsung.tv.home.media`, `home.sidebar`, `coba.newhome`) include 2022 models on Tizen 6.5 and models up to 2025 on Tizen 9 (pull requests [#20](https://github.com/andrearicci93/vetro/pull/20) and [#23](https://github.com/andrearicci93/vetro/pull/23)). The fix is the same one. On Tizen 9 the Launcher still closes only `com.samsung.tv.csfs`, so the memory it frees may be smaller than on the Q80A.
- **Compatibility:** the S90C row now has its model (TQ65S90CATXXC, 2023) and firmware ([#27](https://github.com/andrearicci93/vetro/pull/27), by domenix). The README credits Apps2Samsung for the install-leftovers cleanup ([#21](https://github.com/andrearicci93/vetro/pull/21), by PatrickSt1991).

## 0.3.1 — 2026-10-26

- **Launcher and Home order on TVs with the new Home** (issues #22 and #25): on a UE65BU8002KXXH and a QE75QN85BATXXU (both firmware 1720.7), turning the Launcher on failed with *The Home row is empty or unreadable*. - **Compatibility:** community report from a Samsung UE65BU8002KXXH (2022, firmware T-KSU2EBDEUC-1720.7) on Vetro 0.3.0 (issue #22): service and UID-0 root agent running; the Launcher needed the fix above. Community report from a QE75QN85BATXXU (2022, firmware 1720.7) on Vetro 0.3.0 (issue #25): core functions work, the Launcher failed for the same reason. Report from a Samsung Smart Monitor M8 LS32BM801UNXGO (firmware T-PTMWWC-1720.7, issue #15): service and root agent running, what works not reported yet. Report from a Samsung QN70Q60AAVXZC (2021, firmware T-NKLAAKUC-2310.0, issue #28): working, with the listen port changed because of a clash with tizen-youtube.

## 0.3.0 — 2026-10-25

- **Port clash** (issue #16): the port is no longer fixed at 8099. `VETRO_PORT=9000 node build.cjs` (in `app/` or `rooting/`) writes the port into the widget's access origin, the probe page and the service, so Vetro can sit beside an app that already uses 8099 (tizen-youtube). The default and the default package are unchanged; a port outside 1024–65535, or 8001/8002 (used by the TV's remote sockets), is refused. It is a build-time choice, not a setting on the TV. Not tried on a TV.
- **Installation guide** (issues #11 and #12): a short version at the top (the two packages, what you do and what you do not do), the TV's *Host PC IP → 127.0.0.1* step as its own step 5, and a table for "root agent not connected" that starts from what `/status` shows.
- **Quick settings, privacy curated:** the separate *Privacy* section is gone. Its *ACR viewing data* switch only covered components that **Disable all advertising and tracking** already switches off, so it was a duplicate; the domain filter now sits under *Advertising and tracking*.
- **Launcher, Fix TizenTube:** the switch is greyed out, with the chip *TizenTube is not installed on this TV*, once the app list has been read and TizenTube is not in it (an already-on switch can still be turned off).
- **Diagnostic export:** two new sections, `launcher` (on, running, Samsung’s Home running, Fix TizenTube, Autorun Smart Hub switched off, counts, whether a TizenTube tile exists; never the log, error text or app names) and `quickWins` (auto update, MultiScreen, Ambient). 16 sections in all.
- **Staging folders:** each service start left a new `archive-root-<id>` folder and signed archive in the TV's staging folder (150+ after a few weeks, about 10 MB on a nearly full `/opt`). The service now keeps the current one and the two newest, skips a folder that appears on a running process’s command line (checked in tests only, not yet seen on the TV), and removes the rest and the archives without a folder. Reaches the TV with the next signed build.
- **Launcher (new tab):** a minimal launcher for the Home key (`dock/`, a .NET process run by the TV's own `dotnet`). Turning it on, after an in-page warning, builds its app list from Samsung's own Home row (row order, registry titles and registry icons, read from the TV each time it starts), starts it, and closes Samsung's Home; Settings and Source in the launcher still open Samsung's screens. Nothing is disabled or removed: if the launcher stops, the Home key goes back to Samsung's Home, and Vetro starts the launcher again after a restart or a crash (backing off up to five minutes between tries and never switching itself off, starting it the moment the root helper connects, from the list saved by the last start). Turning the launcher on also switches off Samsung's *Autorun Smart Hub* setting (`db/menu/smart_hub/ontvsetting/auto_start`), so the TV no longer powers on to Samsung's Home; Vetro remembers the old value and puts it back only if it changed it, when the launcher is turned off. Tested on a Q80A only; experimental on other models. While it is on, the tab shows a preview of how the launcher looks on the TV. **Fix TizenTube** (a switch in the same tab) gives the TizenTube tile the YouTube icon and closes Samsung's YouTube (`com.samsung.tv.cobalt-yt`) just before TizenTube starts.
- **Dashboard redesign:** the dashboard now follows the Vetro design system (`app/design-system`: tokens, a reference page and `DESIGN.md`), shows the Vetro icon (served at `/icon.png`) and has a new first group in the navigation: **Quick settings**, **Launcher** (marked Beta) and **Remapper** (the former Remote panel). The Debloater is now **Task manager**. A test keeps the page's tokens identical to `tokens.css`.
- **Quick settings are quick wins:** every switch is worded as the win it gives and *on* means it is applied, with a chip saying *Done* or *Partly done* and a short "What this changes" note. New: **Disable HbbTV** (see below), **Disable MultiScreen autostart** and **Disable automatic firmware update** (`db/menu/support/softwareupdate/autoupdate` 1 → 0 with read-back and rollback; the value that was there is kept and restored on switch-off). Memory figures (HbbTV about 22 MB, Multi View about 15 MB) come from a process survey of a Q80A; the effect of each change on a running TV is not yet verified.
- **HbbTV:** the menu value Off does not stop HbbTV on the Q80A: the app keeps running, and `hbbtv_service` (which listens for app status changes) starts it again at boot, on a source change and when the TV wakes. Tried on the Q80A on 2026-10-23: stopping the app, even with `-k` and with the firmware's own brake file `/tmp/hbbtv_do-not-relaunch` in place, brought it back within 2–4 s; stopping `hbbtv_service` first and then the app kept it off for the 40 s that were watched, and the service did not restart by itself. Off now means the menu value 19, the brake file, the service stopped and the app stopped, in that order, and Vetro does it again after every restart of the TV. Off never starts anything; On removes the two flag files and starts the service and the app. A menu value of Off with the app or its service still running is shown as *Partly done*. Not yet checked: standby and wake, a cold boot, and the red-button deeplink from the TV viewer, which may start the app by another route.
- **MultiScreen:** the TV starts it at boot with a Samsung unit that skips itself when `.../com.samsung.tv.multiscreen/data/disable_preloading` exists; the win creates that file (owned by the app's group) and stops the app, and Multi View still starts on demand. Verified on the Q80A on 2026-10-23: systemd reports the start condition as not met and does not loop. The choices are saved in `vetro-quick-wins.json` in the share folder.
- **Ambient (partial block):** stopping AmbientApp with `-t` or `-k` does not last on the Q80A: it is back within 2–6 s. The process that does it is `screend`, Samsung's screen daemon (the app's launch record names its PID as the caller). `screend` keeps a list of apps to start again when they end, and puts `org.tizen.ambientapp` on it only when the model has the read-only firmware feature `com.samsung/featureconf/ambient_screen_support`; the only built-in brake is a flag it sets while the TV powers off. Neither of its two Ambient settings (`ambient_app_enable`, `ambient_setting`) changes this. So there is no complete block: **Stop Ambient (partial block)** stops the app now and after each restart of the TV (about 59 MB), and says in the dashboard that Samsung may start it again. The disable flag stays unused, because `ambient_start.sh` would retry forever at the next boot. Found by reading the Q80A `screend` binary; the effect on a running TV has only been timed with the stop commands.
- **Quick settings, two all-in switches:** **Disable all advertising and tracking** and **Disable all voice assistants**, each in its own section. Their members are whatever the Task manager files under Advertising and tracking or Voice assistants on the TV, except components with the role *Keep* (Smart Hub's ad agent, which Home loads) and Vetro itself; the list is shown under the switch. They use the same disable flag and rollback as the other groups and stop members that are running. The voice switch asks for confirmation: it also turns off the remote's microphone button, Voice Guide (read-aloud) and voice suggestions in search. The existing per-feature switches (viewing data, Alexa, Bixby, …) stay and show the same state.
- **Domain filter candidates:** `osb.samsungqbe.com`, `rm.samsungqbe.com` and `scs.samsungqbe.com` (found in the firmware, usage unknown) and, labelled *unverified*, `gpm.samsungqbe.com` (a guess at where the viewing-data service learns its servers). `svdca.samsungqbe.com`, which Certificate Manager needs, is on the never-block list.
- **Launcher look:** a new look, chosen in the designer page (`dock/designer`): a solid bar, smaller icons, a thin light line inside every icon, a white focus ring and a glow in the colour of the selected app (ring, glow and icons share one corner radius), the selected icon rising a little, two outline pills (Settings, Samsung Home), a “Source” hint, no name labels or clock, a cascade entrance and constant-speed focus movement. The preview in the Launcher tab follows it.
- **Diagnostics read from seven community reports:** two things had never worked outside the Q80A. The SoC temperature was empty in every report, because Samsung's TVs have no Linux thermal zones; Vetro now reads the driver's own file (`/sys/devices/platform/soc/*thermal/temperature`, whole degrees), which also fills the MQTT temperature sensor. And the CPU rate was empty in four of seven, because its second sample waited behind the slow startup listing in the TV's one-at-a-time command queue; the other reads now start after it.
- **Startup listing no longer times out on slower TVs:** it was one command that needed 13–17 s of `systemctl list-unit-files` work on a Q80A, against a 15 s limit, and the Diagnostics `startup` section came back *unavailable: command timed out* in the QN55Q65, Q65S95C and QN55S95B reports. The running states and the boot states are now two commands (the second with a 60 s limit); if the second fails, the listing still shows what runs, with the boot state unknown. The report gives this section a longer deadline.
- **Compatibility:** community report from a Samsung QN55Q65DAGXZS (2024, firmware T-NKLDUABC-0090-2123.9) on Vetro 0.2.3 (issue #10): built unsigned and loaded with apps2samsung, reported working; the export shows an authenticated UID-0 agent, the service running on Node v18.18.2 and 29 confirmed controls. Cold-boot persistence was not reported.
- **Compatibility:** community report from a Samsung Q65S95C (2023, firmware T-PTMCDEUC-0090-2220.4) on Vetro 0.2.3 (issue #13): service running on Node v18.18.2 with an authenticated UID-0 agent, 23 voice-assistant and ACR components disabled from Quick settings, button remaps in use, and 29 of 29 controls confirmed.
- **Compatibility:** community report from a Samsung QN55S95BAFXZA (2022, Tizen 6.5, firmware T-PTMAKUC-1720.7) on Vetro 0.2.3 (issue #14): root on the first try, the TV rooted itself after the Host PC IP step, and 15 of 17 ad and analytics packages were disabled and verified. Only 267 of its 368 packages are in the Q80A-based catalog.
- **Installation guide** (issues #11 and #12): a short version at the top (the two packages, what you do and what you do not do), the TV's *Host PC IP → 127.0.0.1* step as its own step 5, and a table for "root agent not connected" that starts from what `/status` shows.
- **TV page:** opening Vetro now also tries to start the background service (`tizen.application.launch('vetrotvapp.svc')`) and retries the service check for about 12 seconds, because a public-level certificate may not get the on-boot start honored (issue #2). No extra privilege is declared. Tested by a contributor on a Q60A (Tizen 6, personal certificate), where the service started on every launch. On the Q80A the call is accepted, but the system restarts the stopped service by itself within a second, so starting from a stopped service could not be reproduced there. The page also says when the service did not answer.
- **TV page:** the small Vetro page on the TV closes itself 5 seconds after the report reaches the service (or when it is hidden after that), instead of staying resident. On the Q80A its web app and web process held about 100 MiB of resident memory (RSS, which includes shared pages) in a benchmark sample; the service keeps running. A failed report leaves the page open so the error can be read. The Debloater keeps Ambient Mode (`org.tizen.ambientapp`) off the disable list, with a test, because the firmware's boot script relaunches it in a retry loop.
- **TV picture controls:** blur reduction, judder reduction, LED Clear Motion and HDMI black level can now be changed from Settings. They are firmware-derived: the D-Bus signatures come from the Q80A `avocd` handlers, and for HDMI black level (0–2) and LED Clear Motion (0–2) the decompiled menu provider passes the menu value straight to the call; for blur reduction the call is visible but not its arguments, and judder reduction was not decompiled. None has been written on a TV by the maintainer. Each is editable only after the TV's own `busctl introspect` lists the exact method and signature; otherwise the row stays read-only with the reason, and a failed check never touches the six controls verified earlier. Writes keep the read-back and rollback of the existing controls. The method list is fetched once per service run. The diagnostic export now records, for every control, whether the TV exposes it (`confirmed`, `missing`, `signature-mismatch`) and how many methods it offers, so a report from another model shows which controls it supports.
- **Diagnostic export:** sections that fail now carry a fixed-list `reason` and, for failed commands, the numeric exit code, so a missing section such as `startup` can be diagnosed from the file. Startup listing now tells a command timeout from a command failure.
- **Diagnostic export:** model, firmware and API probe are labelled as widget-reported with their age; settings write paths are reported as `implemented` instead of `verified`; the monitor takes two samples so CPU rates are filled in; the temperature is searched across all thermal zones; kernel threads are counted instead of listed; the dead `runtimeAvailability` field and idle Wi-Fi services are no longer exported; `anynet+(hdmicec)`-style menu ids are kept; `sourceDirty` records whether the package matched its revision.
- `POST /probe` is accepted only from the TV itself.
- **Domain filter candidates** now come from hostnames found in the Q80A firmware (advertising, analytics and KPI, diagnostic logs), shown in groups with their evidence; the earlier public-report names stay in a separate group. The filter refuses the names the TV uses for its internet check and clock, and `/blocklist` no longer lists the `samsungcloudsolution.com` parent domain, which external blockers would apply to those names. See [domain filter candidates](app/docs/DOMAIN-FILTER.md). Other write routes are unchanged.
- **Community report analysis:** structured reports no longer match text error signatures, and the review names the sections that were not collected and why.
- **Compatibility:** community report from a Samsung Q70A (QE55Q70AATXXC, firmware T-NKM2DEUC-2301.1) on Vetro 0.2.3: setup with root access completed, Quick settings, the Debloater and domain blocking used, and the diagnostic export confirmed 29 controls against the TV's own method list. The reporter also turned the red standby LED off and on again through the firmware's `micom_set_standby_led_state` (libmicom), outside Vetro; this is not a Vetro feature yet, and the library has no matching getter, so a switch could not read the state back. Turning off the Enlightenment effects module did not remove the Home and Settings animations.
- **Compatibility:** community report from a Samsung QN85A (GQ65QN85AATXZG, firmware T-NKM2DEUC-2301.1) on Vetro 0.2.3: app, service and UID-0 agent working and recovered after a reboot, once the reporter had enabled the service's on-boot and auto-restart flags. Installation guide: a DNS filter blocking `svdca.samsungqbe.com` makes Certificate Manager fail.
- **Compatibility:** first community diagnostic report from a second model, a Samsung Q67B (QE43Q67BAUXXH, firmware T-NKLBDEUC-1720.7), on Vetro 0.2.3. The app and service were running, the authenticated root agent was connected with UID 0, and 32 components were disabled through the registry. Not confirmed: cold-boot persistence and the system service listing, which was unavailable in that report.
- **Quick settings** is the first panel: switches for HbbTV, domain blocking, Alexa, Google Assistant, Bixby and voice services, with in-page confirmation for voice switches (the remote microphone button stops working). Groups apply the disabled flag to every installed member in one step, verify it in the registry, roll back on failure and stop members still running.
- **Install leftovers** cleanup ported from Apps2Samsung (MIT): package files in the install staging folder, deleted one at a time, with bytes freed and storage before and after. Refused while an installation is running.
- **App catalog** from the firmware manifests: area, role and purpose for each package; references from other packages, event and key-sequence launches and microphone/camera/location access in the component drawer. `app/scripts/build-app-catalog.py` regenerates `service/app-facts.js` from a private dump.
- **Debloater** layout: role filters with counts, one State column, Startup listing only flags that are on, CPU/RAM only while sampled, duplicate names disambiguated, startup flags as switches.
- The Remote panel polls only while listening; stopping capture returns to the saved interception choice.
- Navigation grouped by task; HbbTV, domain blocking and MQTT use switches; privacy values use words instead of Yes/No.
- Dashboard live sampling starts off. **Start live** samples the TV for 2 minutes and stops by itself; opening a component drawer takes one sample when process data is stale.
- CPU, network and paging rates restart after a gap of more than 60 seconds instead of reporting an average over the idle period.

## Source preview — 2026-10-11

- Minimal dark dashboard with English product copy and explicit app/process/startup states.
- Grouped component inventory with package/family boundaries and unknown-state handling.
- Redacted JSON diagnostic downloader and current platform/root status fields.
- Issue form, deterministic community report analysis and bot-comment workflow.
- Separate app-only and privileged integration packaging, with integration-boundary tests.
- Explicit signing credentials, original-code MIT license and upstream notices.
- Public installation/compatibility documentation with measured performance limitations.
- Private raw reports, device certificates and signed test packages excluded from the current tracked snapshot.

Vetro 0.2.0 is installed on the test TV. Dashboard contents, all 14 diagnostic sections and continued background operation after closing the app are verified. Unattended cold boot of this version remains to be tested. Private historical Git data is archived outside the fresh publication repository.
